# Frontend integration boundary

`verify-design-boundary.cjs` compares the current frontend with the reviewed upstream app. Run it from `taxi/` with `TAXI_BASELINE_DIR` pointing to that app directory.

The original design-only check assumed that functional handlers would stay byte-for-byte unchanged. The current integration also fixes request serialization, confirmation recovery, deadlines, boarding codes, money input and GPS projection. These differences are reviewed explicitly in `reviewed-integration-20261103.json`.

Each reviewed source has an exact baseline hash, an exact implementation hash, a rationale and related regression-test paths. New helper files must be absent from the baseline. An exception applies only to the named difference at those exact versions. Unknown differences, missing evidence or altered code fail the check. The manifest is not regenerated by the verifier. A code change requires another review and an intentional manifest update.

The baseline is upstream commit `1d4065058c90e9ad39dfb301bc3affc3da8847a5`, an ancestor of this branch. This is distinct from `8cd07c90`, the earlier commit discussed in Valentin's original audit. CI checks out the pinned baseline separately. The `--design-only` option retains the old comparison and deliberately reports the integration differences as out of that older scope.

This is a static source boundary. It does not replace unit, TypeScript, build, browser, backend, physical-device or load tests. The public Offer marker, persisted ETA/comment and PIN-check action require the separately documented backend rollout. A passing local verifier does not mean that the server or FSM service has been deployed or accepted.
