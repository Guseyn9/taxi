Два варианта для Валентина

A Universal API

Перенести совместимый пакет и принять Universal для трёх режимов. Гарантии безопасности, денег, атомарности и эксплуатации обязательны. Полная FSM-миграция может идти следующей очередью.

B Новый FSM в первом пилоте

Принять пользовательские Query/Command/Status/WS, durable/idempotent выполнение, фактические snapshots и recovery; затем выполнить полный dev E2E через этот сервер. Переключение env не заменяет серверную реализацию. Для потерянного ответа нельзя слепо повторить write или автоматически перейти на Legacy.

Решение принимает Валентин. Оба варианта подготовлены; молчание не считается выбором A. Для B необходимы реальный backend-контракт и отдельная оценка по его коду. Подробные варианты и endpoints.

QA одного готового кандидата следует планировать отдельным этапом, а не совмещать с бесконечным изменением кода.

Деньги и время

Утвердить MAD или другую фактическую валюту, единицы хранения, округление, комиссию и возвраты на сервере. GHS архивного стенда и EUR прочитанного dev не становятся MAD заменой подписи. Клиент показывает серверный результат.

В архивном приложении остаётся жёсткая Europe/Kiev. Настройка PHP ini Africa/Casablanca её не заменяет. Нужна принятая tenant-политика PHP/БД/API, отложенные поездки, смена суток и DST. Реальные полигоны, лицензии и классы подтверждает владелец сервиса.

Приёмка и откат

Принимать один набор frontend/backend/schema/dictionary/config с commits и временем установки. Зафиксировать результаты API и UI обеих ролей на одних order IDs. Повторить отказ, потерянный ответ, повтор команды и смену аккаунта; подтвердить серверное состояние и итоговую сумму.

Провести restore rehearsal. После записи новых password hashes нельзя вернуть MD5-only verifier; rollback должен сохранять совместимый вход. Не откатывать БД поверх новых поездок и не удалять новые options автоматически. Назначить дежурного, канал поддержки и критерии остановки пилота.

Предлагаемый нагрузочный профиль: 200 и 400 водителей, реальное пассажирское чтение/команды, 60 минут штатной нагрузки и одновременные reconnect. Пороговые latency/error/recovery показатели утвердить до теста; локальные unit/E2E не считаются измерением этих SLA.

Дополнительные backend исправления вне исходных заголовков

  • Регистрация: bound queries, безопасные типы, роли/контакты/referral и ошибки DB; обычные сценарии сохранены.
  • Общий lookup пользователя: prepared SELECT на текущем role-specific connection, self guard после SQL comparison, действительная роль администратора и сохранение исходной cookie.
  • Автоматические PHP errors: generic response с request_id, metadata-only журнал, отключён request debug capture. Исторические журналы и отдельные scratch endpoints требуют действий администратора.

Это локальные исправления присланного архива. Все оставшиеся SQL/authorization пути целиком не просканированы и не объявлены безопасными. Для пилота ограничить реально включённую поверхность API и проверить её роли/права.

Что передать и что вернуть после dev

Передать полный release-пакет с backend patch/source, frontend source manifest, миграцией, preflight, регрессиями, этой сводкой и START_HERE. Старые ZIP применять по очереди не требуется. Не переносить тестовый стенд, пароли и fixture router на сервер.

После переноса вернуть: backend/frontend URL и commits, tenant, PHP/БД/schema/dictionary, выбранный вариант API, результаты с ID тестовых заказов, список открытых обязательных gates и ответственных. Доступы, полные конфиги и authentication traces в общий чат не отправлять.
