Реальные данные tenant

API: taxi_dev2/c/gruzvill/api/v1. Словарь: taxi_dev2/cache/data_gruzvill.js. Их версии совпали при проверке. HTTP 200 и code=200; cache-version доступен с Origin Vercel. Всего 680 ключей основного словаря, 15 записей полигонов. Наличие записи полигона не означает проверку его геометрии или прав сохранения.

Наличие всех девяти языков восстановлено. Полнота перевода не 100%: заполнено от 632 до 677 из 680 ключей в зависимости от языка; для новых frontend-текстов возможен fallback. Лингвистическое качество переводов отдельно не оценивалось.

Для Darija арабским письмом исправлен RTL; латинские Darija/Tamazight и Tifinagh остаются LTR. Все девять кодов сохраняются в html lang.

Настройки Марокко требуют исправления на стороне владельца данных.
  • default_currency=GHS и currency_of_the_service=GHS, знак $; MAD есть в справочнике, но не выбран валютой сервиса.
  • Country_service=GHA и маска +233 расходятся с default_country=ma / service_country=ma.
  • account_currency_list=RUB; шесть записей tariffs имеют USD. Назначение каждого тарифа (включая подписки) должен подтвердить владелец — это не доказательство валюты поездки.
  • В строке Español указаны tr_code=ar и logo=ma. Сам интерфейс использует ISO es; метаданные нужно перепроверить у источника.

На frontend эти значения не маскируются заменой символа валюты: сумма и расчёты должны согласовываться с сервером.

Очередь до production

  1. Валентин / владелец backend: конфигурация gruzvill. Сверить реальную БД и таблицы настроек, выбрать согласованную валюту MAD, страну/телефон и утверждённые тарифы. Пересобрать cache штатным механизмом, сверить версию JSON и JS. Секреты БД не передавать во frontend.
  2. Frontend: самостоятельные исправления. Передать точный patch/manifest текущей версии автору аудита; отдельно закрывать URL-эмулятор, секреты в строковых логах, uploads, оставшиеся UI/error/recovery и dependency-пункты с регрессиями. Не переписывать архитектуру и API по догадкам. Не смешивать ветку аудита с исправлениями.
  3. Backend: аудит и применение согласованного кандидата. Роли и tenant isolation, токены/revocation, регистрация/пароли/ошибки, PIN, владение заказом, идемпотентность терминальных команд, quote/settlement, файлы и location TTL. Наш r5 проверен только локально; факт его установки на общий dev не подтверждён.
  4. Интеграция: два варианта для решения Валентина. Legacy Universal: действующий /api/v1, существующие поля и readback, серверный PIN и подтверждённые ошибки. FSM: командный endpoint через пользовательскую сессию/прокси, стабильный command ID, status до terminal result, snapshots/reconnect; общий секрет в браузер запрещён. FSM остаётся выключен до готовности сервера. Валентин выбирает вариант пилота после проверки обоих контрактов.
  5. Совместный QA на gruzvill. Две роли и два браузерных контекста: Standard, Voting, Offer, выбор/отказ, неверный/чужой/повторный PIN, старт, отмена/завершение одновременно, разрыв сети после POST, reload, смена аккаунта, рейтинг с readback. Для зон: админ сохраняет и читает результат; обычный пользователь получает отказ. Все операции — только согласованные тестовые аккаунты/заказы.
  6. Устройства и выпуск. Реальные Android/iOS/WebView, портрет/альбом, GPS, отказ разрешений и возврат из фона, медленная сеть. Зафиксировать frontend artifact + backend commit + tenant/cache version. Подтвердить резервную копию БД, мониторинг ошибок/команд и проверенный rollback; затем ограниченный пилот, после него допуск в production.
