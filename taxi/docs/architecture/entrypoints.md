# Точки входа фронтенда

Проверено 04.11.2026 в отдельном frontend. Оригинальный репозиторий и backend не изменялись.

## Что редактировать

| Задача | Точка входа | Источник конфигурации |
| --- | --- | --- |
| Запуск приложения | `npm start` → `scripts/start.js` → `src/index.tsx` | `config/webpack.config.js`, `config/webpackDevServer.config.js`, `config/env.js` |
| Production-сборка приложения | `npm run build` → `scripts/build.js` | Те же корневые `config/*`; `tsconfig.json` в корне |
| Сборка приложения и материалов для проверки | `node tools/build-release.cjs` | Корневой Webpack; отдельные entry для QA и investor; проверенный PDF |
| Unit-тесты | `node scripts/test.js --watchAll=false --runInBand` | Раздел `jest` в `package.json`; `config/jest/*` |
| TypeScript | `npm run typecheck` | Только корневой `tsconfig.json` |
| Браузерные сценарии | `playwright.config.ts`, `e2e/*.spec.ts`, `e2e/auth.setup.ts` | Аккаунты и адрес стенда передаются вне публичной сборки |
| QA / формы | `src/qa/cjm-entry.tsx`, `src/qa/auth-entry.tsx` | `tools/build-cjm.cjs`; синтетические данные, без изменения реальных заказов |
| Локальные проверки карты, HTTP, стилей и восстановления | Соответствующие `src/qa/*-entry.*` | Изолированные harness в `tools/*browser.cjs` |
| Investor demo | `src/design/investor/entry.tsx` | `tools/build-investor.cjs`; отдельный сценарий без bootstrap рабочего приложения |
| Отдельный эмулятор разработчика | `driver-emulator/src/control-panel.js` и его CLI | Собственная конфигурация; не часть browser bundle |

`src/config.ts` — рабочая загрузка настроек сервиса. Это не Webpack-конфигурация. Импорты `../config` из кода приложения разрешаются в этот файл, а не в соседнюю папку `src/config`.

## Сохранённые совместимые пути

- Девять файлов в `src/config`, включая два Jest transform, только перенаправляют вызов в `config/*`. Их нельзя править как вторую конфигурацию. Совместимость проверяется существующими тестами `clientEnvironment.test.js`.
- `src/lib/ui-utils.ts` используется компонентами shadcn. Папка `src/lib` не удалена целиком.
- `lib/react-dev-utils` подключён как локальная зависимость и используется скриптами сборки/запуска. Его лицензия сохранена.
- `lib/react-leaflet-fullscreen-plugin` сохранён как объявленная локальная зависимость с лицензией. Наличие в manifest не считается доказательством импорта в текущем browser entry.
- `src/platform/adapters/Legacy*` — действующая граница API, а не старые копии. Карты клиента и водителя обслуживают разные роли; их не удаляли как дубли.
- Архивные отчёты и дизайн-референсы остаются в `docs`/`review`. Публичные изображения и импортируемые assets могут иметь разные URL и способы доставки; совпадение картинки само по себе не основание для удаления.

## Что удалено

52 файла без входящих ссылок из остальных модулей: копии `react-dev-utils` и fullscreen plugin из `src/lib`, вложенные `scripts/scripts`, три вложенных `tsconfig.json` и `package_fixed.json`.

Перед удалением построен статический граф импортов и `require`: 1 232 разобранных файлов, 269 корневых entry/test/tool, 774 достижимых модуля. Ни один удаляемый файл не достижим; входящих ссылок и неразрешённых локальных импортов нет. После изменения разобрано 1 195 файлов; добавлена проверка структуры. Статический граф не заменяет сборку или проверку поведения.

Динамические загрузки проверены отдельно: две палитры SVG, разрешённые пути к корневому package/tsconfig/proxy, Sass loader, установленный TypeScript и поиск имени package локального процесса. Они не обращаются к удалённым копиям.

## Как не вернуть дубли

`npm run check:entrypoints` проверяет наличие канонических файлов, отсутствие удалённых путей, локальные зависимости из `lib/` и то, что совместимые `src/config/*` остаются простыми перенаправлениями. Проверка включена в `pre-build.js`, общий frontend check и отдельную задачу GitHub Actions. Локальный запуск CI-проверки не означает, что workflow уже прошёл на GitHub.

Негативные проверки выполнялись во временной копии: возвращённый `public/tsconfig.json`, копия библиотеки внутри `src`, изменённый shim, команда со вложенным script и отсутствующий runtime entry отвергаются.

## Восстановление

До удаления сохранены все 52 файла с SHA-256 вне каталога публикации. Ветка и Git HEAD не изменены; все удалённые файлы были отслеживаемыми и не содержали локальных правок.

Список удалённых путей и контрольные суммы находятся в `entrypoints-verification.json` рядом с QA-отчётом. Восстанавливать следует только эти пути из исходной версии или локального архива, предварительно проверив, что по ним не появились новые файлы. Проверку структуры нужно менять осознанно вместе с восстановлением, иначе она остановит сборку.
