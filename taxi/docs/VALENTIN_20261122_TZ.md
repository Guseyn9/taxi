## Сбой обновления заказов

- В r20 текст предупреждения срабатывает при неудачном чтении списка активных заказов или карточки подтверждённой поездки. Ветка списка использует `POST /drive?fields=00000000u1` с `array_type=list`. Готовые заказы и история используют `/drive/now` и `/drive/archive`. HTTP и код в ответе сервиса различаются.
- До исправления повреждённое локальное хранилище `hiddenOrders` могло прервать вызов до отправки HTTP. Успешный ответ с заказами и без вспомогательного справочника `user` тоже мог вызвать исключение в браузере. Теперь валидный ответ обрабатывается в обоих случаях. Если сам список некорректен, остаются последние действительные данные. Следующее успешное обновление заменяет их.
- Новая запись `ORDER_LIST_READ_FAILURE` доступна в существующем RAW-журнале. Она содержит признаки сетевой ошибки, таймаута, отказа HTTP или сервиса, неправильной структуры либо ошибки преобразования. В запись попадают только заданные поля и известные причины, например отсутствие активной машины. Тело, заголовки, параметры авторизации и сведения о заказах в эту запись не добавляются.
- Исторический снимок не содержит трассы. Для окончательного вывода нужен журнал исходной ошибки или повтор сбоя на авторизованном аккаунте водителя в `gruzvill`. Из журнала достаточно самой записи с временем, методом, путём, HTTP-статусом и кодом сервиса.
- Регрессии покрывают повреждённое хранилище, отсутствующий справочник, сохранение скрытых заказов, ответ с битым списком, отказ сервиса при HTTP 200, HTTP 503, таймаут, сохранение предыдущего списка и восстановление после следующего чтения.

## Universal MCP

Архив из Telegram `ibronevik-taxi-mcp-feature-aggregate (1).zip` прочитан локально. Подтверждены транспорт stdio, реестр операций, авторизация сервиса и режимы записи `block`, `confirm`, `allow`. Архив включает серверный модуль агрегатов с отдельной установкой в существующий бэкенд. Пригодность как основы для серверного MCP подтверждается структурой адаптера. Публикация требует серверного транспорта, аутентификации клиентов MCP, ограничения tenant и набора читающих методов; режим `block` и отсутствие записи следует проверить на локальном стенде. Внешний шлюз можно оценивать как отдельный вариант транспорта и контроля доступа, когда известны его контракт, развёртывание и модель хранения ключей. Серверный запуск архива и стороннего шлюза не проверен.

## Совместимость с архивным справочником

На изолированном стенде из присланного архива `/data` возвращает `car_classes` как массив: PHP кодирует последовательные идентификаторы `0…5` таким образом. Прежняя проверка отклоняла весь справочник и блокировала вход в интерфейс. Фронтенд теперь принимает массив объектов и сохраняет индексы как идентификаторы. Формат `gruzvill` с объектом продолжает использоваться напрямую. Регрессионные тесты покрывают сохранение класса `0` и отказ на повреждённый массив.

## Загрузка настроек сервиса

Для V10 при сетевом сбое, таймауте или временном отказе HTTP фронтенд сам повторяет чтение `GET /data` один раз. Общий лимит загрузки составляет 15 секунд. Переключение тенанта отменяет предыдущий запрос. При некорректном справочнике, включая пустой список классов машин, интерфейс показывает «Не удалось загрузить настройки сервиса» и кнопку «Повторить». Событие `TENANT_DICTIONARY_READ_FAILURE` записывает распознанную причину, доступные коды и время без содержимого ответа.
