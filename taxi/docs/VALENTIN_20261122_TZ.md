## Сбой обновления заказов

- В r20 текст предупреждения срабатывает при неудачном чтении списка активных заказов или карточки подтверждённой поездки. Ветка списка использует `POST /drive?fields=00000000u1` с `array_type=list`. Готовые заказы и история используют `/drive/now` и `/drive/archive`. HTTP и код в ответе сервиса различаются.
- До исправления повреждённое локальное хранилище `hiddenOrders` могло прервать вызов до отправки HTTP. Успешный ответ с заказами и без вспомогательного справочника `user` тоже мог вызвать исключение в браузере. Теперь валидный ответ обрабатывается в обоих случаях. Если сам список некорректен, остаются последние действительные данные. Следующее успешное обновление заменяет их.
- Новая запись `ORDER_LIST_READ_FAILURE` доступна в существующем RAW-журнале. Она содержит признаки сетевой ошибки, таймаута, отказа HTTP или сервиса, неправильной структуры либо ошибки преобразования. В запись попадают только заданные поля и известные причины, например отсутствие активной машины. Тело, заголовки, параметры авторизации и сведения о заказах в эту запись не добавляются.
- Исторический снимок не содержит трассы. Для окончательного вывода нужен журнал исходной ошибки или повтор сбоя на авторизованном аккаунте водителя в `gruzvill`. Из журнала достаточно самой записи с временем, методом, путём, HTTP-статусом и кодом сервиса.
- Регрессии покрывают повреждённое хранилище, отсутствующий справочник, сохранение скрытых заказов, ответ с битым списком, отказ сервиса при HTTP 200, HTTP 503, таймаут, сохранение предыдущего списка и восстановление после следующего чтения.

## Universal MCP

Архив из Telegram `ibronevik-taxi-mcp-feature-aggregate (1).zip` содержит транспорт stdio, реестр операций, авторизацию сервиса и режимы записи `block`, `confirm`, `allow`. Серверный модуль агрегатов устанавливается в Core отдельно. Реестр архива описывает маршруты, способ передачи ID и классификацию операций. Для перехода к серверному MCP требуется проверить транспорт, аутентификацию клиентов, права на tenant и способ выдачи читающих методов.

Без сетевого доступа прошли 51 тест маршрутизации, замены реестра и агрегатов, а также TypeScript. Архивный процесс ответил на `initialize` и перечислил 13 инструментов через stdio. В режиме `block` он отклонил создание заказа при вызове инструмента с явным подтверждением.

По описанию разработчика TaoBridge умеет публиковать инструменты через MCP, проверять аргументы, разграничивать доступ по действию и tenant и журналировать вызовы. Это может ускорить общий вход в несколько MCP и выдачу прав на уже описанные операции. Доменному MCP всё равно нужны схема заказа, роли, правила переходов поездки и подтверждение результата через Core. [Описание TaoBridge от разработчика](https://thinkingos.tech/blog/taobridge-action-server).

Для первого пилота достаточно чтения справочника `car_classes` в согласованном тестовом tenant. Критерии проверки покрывают совпадение результата прямого и проксированного чтения, отказ для другого tenant и отсутствие HTTP-вызова на запись при запрещённой команде. Решение о подключении зависит от подтверждённой совместимости с авторизацией Universal API, размещения шлюза и модели хранения ключей. Эти условия для связки TaoBridge и Core пока не проверены.

## Совместимость с архивным справочником

На изолированном стенде из присланного архива `/data` возвращает `car_classes` как массив: PHP кодирует последовательные идентификаторы `0…5` таким образом. Прежняя проверка отклоняла весь справочник и блокировала вход в интерфейс. Фронтенд теперь принимает массив объектов и сохраняет индексы как идентификаторы. Формат `gruzvill` с объектом продолжает использоваться напрямую. Регрессионные тесты покрывают сохранение класса `0` и отказ на повреждённый массив.

## Загрузка настроек сервиса

Для V10 при сетевом сбое, таймауте или временном отказе HTTP фронтенд сам повторяет чтение `GET /data` один раз. Общий лимит загрузки составляет 15 секунд. Переключение тенанта отменяет предыдущий запрос. При некорректном справочнике, включая пустой список классов машин, интерфейс показывает «Не удалось загрузить настройки сервиса» и кнопку «Повторить». Событие `TENANT_DICTIONARY_READ_FAILURE` записывает распознанную причину, доступные коды и время без содержимого ответа.

## Запуск эмуляторов на локальном стенде

Для V16 в «Инструментах тестирования» откройте панель нужной роли и выберите JSON с одноразовыми аккаунтами локального Core. Приложение и Core должны открываться с локальных адресов. Подключение берётся из настроек приложения. Данные аккаунтов хранятся в памяти до выхода из приложения, смены аккаунта или перезагрузки.

```json
{
  "drivers": [{"name": "Водитель QA", "login": "driver@example.invalid", "password": "<тестовый пароль>", "type": "e-mail"}],
  "clients": [{"name": "Пассажир QA", "login": "client@example.invalid", "password": "<тестовый пароль>", "type": "e-mail"}]
}
```

В файле достаточно списка нужной роли. У водителя должны быть одобренный тестовый аккаунт и машина. Для воспроизводимой подачи можно добавить аккаунту `"location": {"latitude": 30.416, "longitude": -9.581}`. Затем нажмите «Проверить» и «Запустить». Чтобы завершить сессию и закрыть созданные клиентским эмулятором тестовые заявки, нажмите «Остановить» до выхода.

## Приёмка посадки и старта поездки

Для поездки без кода посадки ожидается одна команда `set_start_state` и подтверждённый сервером переход в `Started`. Если для поездки задан код, отдельно проверяются отказ с неверным кодом, старт с действительным кодом, двойное подтверждение и восстановление состояния после перезагрузки. В сквозном тесте при отказе сохраняются наличие формы, последовательность `check_driver_code` и `set_start_state`, HTTP-статус и код сервиса. Код посадки, токен и текст ответа исключены из этой записи.

## Прямая ссылка на карточку водителя

Для V10 проверяется вход с главного экрана водителя и с прямой ссылки `/driver-order/:id`. Гость видит кнопку входа, а приложение загружает карточку после появления сессии. При успешном входе с ролью водителя открытой остаётся та же ссылка с query и hash. Вход под ролью пассажира ведёт на пассажирский экран.
