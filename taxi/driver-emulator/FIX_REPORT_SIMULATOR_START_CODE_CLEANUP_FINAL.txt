Что исправлено в симуляторе:

1. Старт поездки после статуса «на месте»
   Для обычных заказов и offer-заказов бот теперь запускает поездку без кода посадки. После успешного set_arrive_state он сразу пробует set_start_state без b_driver_code. Если backend вдруг всё же отдал код, код используется только как запасной вариант.

2. Voting / голосование
   Для голосования добавлен тестовый перебор кода посадки от 1 до 9 включительно. Сначала используется реальный b_driver_code, если backend его вернул, затем бот пробует 1,2,3,4,5,6,7,8,9.

3. Исправлена ошибка определения voting
   Раньше строка b_voting="0" могла считаться как true, потому что Boolean("0") в JS возвращает true. Из-за этого обычный заказ мог ошибочно попасть в логику voting и ждать код. Теперь флаги проверяются безопасно: true / 1 / "1" / "true".

4. Offer/voting остаются ручным выбором клиента
   В offer и voting водитель только отправляет кандидата performer=0. Движение начинается только после того, как клиент сам выбрал водителя. Для обычного заказа direct performer снова разрешён, потому что там нет клиентского листания кандидатов.

5. Старые зависшие заказы тестовых аккаунтов
   На старте симулятор проверяет активные заказы каждого тестового водителя. Если у аккаунта висит старый/предыдущий активный заказ, он отменяется через set_cancel_state, чтобы аккаунт снова мог предлагать услуги. Это должно исправить ситуацию, когда второй аккаунт не появляется в кандидатах из-за старого активного состояния.

6. Настройки в config.json
   autoStartTrip=true, autoStartRequiresCode=false, startAfterArriveMs=0, votingStartCodeCandidates=[1..9], cleanupOldActiveOrders=true, cancelExistingActiveOrdersOnStart=true.

Проверка:
node --check driver-emulator/src/simulator.js
