# Эмулятор водителей для taxi / offer / voting

Это отдельная папка. Её не надо класть внутрь фронта. Скрипт нужен для теста: он логинит несколько водителей, смотрит новые заказы и автоматически отправляет отклики с разной ценой, подачей и комментарием.

Ссылки на старые чаты ChatGPT из сообщения открываются только как страница с заголовком, без полного содержимого, поэтому в архиве я сделал рабочий вариант по коду регистрации и по текущему ТЗ: регистрация тестовых водителей, проверка логинов/машин, постоянный эмулятор откликов, отдельный режим dry-run.

## Что внутри

- `src/register-drivers.js` — регистрирует тестовых водителей и создаёт им машины.
- `src/simulator.js` — запускает водителей и отправляет отклики на заказы.
- `config.json` — главный файл настроек.
- `data/registered-drivers.json` — сюда сохраняются созданные водители после регистрации.
- `run.bat`, `check.bat`, `run-once.bat`, `register.bat`, `doctor.bat` — запуск двойным кликом на Windows.

## Что умеет

- регистрировать 1, 10 или любое количество тестовых водителей;
- создавать машину после регистрации;
- логиниться под каждым водителем;
- проверять, что у водителя есть машина;
- искать заказы через `/drive/now`;
- откликаться на обычное голосование и offer/предложение;
- отправлять цену водителя;
- отправлять подачу `driver_offer_eta`;
- отправлять комментарий `driver_offer_comment`;
- делать задержку реакции, чтобы водители появлялись не одновременно;
- делать разную цену каждому водителю;
- работать в безопасном режиме, если backend ругается на `wrong c_options keys`.


## Если при регистрации пишет busy user data

Это значит, что такие email/телефоны уже есть на backend. В версии v3 регистрация создаёт уникальный `Run ID` и добавляет его в email/телефон/номер машины, поэтому старые занятые `testdriver_001@...` больше не используются.

Правильный порядок:

```bat
npm run register
npm run check
npm start
```

Если хочешь заново создать свежих водителей, можно удалить старый файл:

```bat
del data\registered-drivers.json
npm run register
```

Важно: `drivers` из `config.json` теперь не используются, пока не поставить `"useConfigDrivers": true`. Это сделано специально, чтобы старые тестовые логины `driver1@test.com` не ломали проверку `wrong login`.

```json
  "phonePrefix": "+1000",

  "carNumberPrefix": "TEST",
  "carColorId": "1",
  "carClassId": "1"

```

Потом запусти:

```bat
npm run register
```

Или нажми `register.bat`.

После успешной регистрации появится файл:

```bat

```

Эмулятор будет брать водителей из этого файла автоматически.

## Важно про номера телефонов

Сейчас по умолчанию стоит не российский шаблон:

```json
"phonePrefix": "+1000"
```

Если backend требует другой формат, поменяй только `phonePrefix`. Например:

```json
"phonePrefix": "+212600"
```

## Как тестировать с сайтом

1. Запусти пассажирский сайт.
2. Запусти эмулятор:

```bat
npm start
```

3. У пассажира создай заказ через `Голосование` или `Предложение`.
4. В консоли эмулятора появится примерно:

```text

```

5. У пассажира должны появиться водители в выборе.

## Настройка откликов

В `config.json` есть блок:

```json
"defaultOffer": {
  "minPrice": 100,
  "maxPrice": 180,
  "etaOptions": [
    "Буду через 5 минут",
    "Буду через 10 минут",
    "Буду через 15 минут",
    "Буду через 20 минут",
    "Буду через 30 минут"
  ],
  "commentOptions": [
    "Еду напрямую",
    "Есть кондиционер",
    "Большой багажник",
    "Могу быстро подъехать"
  ]
}
```

Каждый водитель случайно берёт одно значение подачи и один комментарий.

Для конкретного водителя можно переопределить:

```json
{
  "name": "Fast Driver",
  "login": "fast@test.com",
  "password": "123456",
  "type": "e-mail",
  "acceptProbability": 1,
  "reactionDelayMs": [500, 1500],
  "priceDelta": [0, 10],
  "etaOptions": ["Буду через 5 минут"],
  "commentOptions": ["Еду напрямую"]
}
```

## Важная настройка offerTransport

```json
"offerTransport": "c_options"
```

Это значит, что эмулятор отправляет в `c_options`:

```json
{
  "performers_price": 125,
  "driver_offer_eta": "Буду через 15 минут",
  "driver_offer_comment": "Большой багажник"
}
```

Если backend снова пишет:

```text
wrong c_options keys: driver_offer_eta,driver_offer_comment
```

значит backend не читает нужную константу или использует кеш. Тогда можно временно поставить:

```json
"offerTransport": "separate"
```

или оставить:

```json
"retrySafeOnWrongCOptions": true
```

Тогда эмулятор не будет падать: он повторит отклик только с ценой, но комментарий и подача могут не сохраниться, если backend их не принимает.

## Режим без отправки откликов

```bat
npm run dry
```

Он покажет, какие заказы нашёл и что бы отправил, но реально backend не изменит.

## Частые ошибки

### wrong login / wrong password

Неверный логин или пароль в `config.json` или `data/registered-drivers.json`.

### car not found

У водителя нет машины. Перерегистрируй водителей или зайди под водителем и добавь машину вручную.

### used_car_not_found

Backend не видит активную машину водителя. Проверь `carModelId`, `carColorId`, `carClassId`, `carSeats`, привязку машины и статус водителя.

### wrong c_options keys

Backend не принимает ключи `driver_offer_eta` и `driver_offer_comment`. Проверь backend-константу именно для того конфига/`st_id`, где создаётся заказ:

```json
{"performers_price":true,"driver_offer_comment":true,"driver_offer_eta":true}
```

После изменения константы перезапусти backend или сбрось кеш, если константы кешируются.

### Нет заказов

Проверь:

- заказ реально создан у пассажира;
- правильный `apiBase`;
- водитель подходит по классу машины;
- водитель подходит по локации/городу;
- заказ не уже назначен другому водителю;
- `orderType` не ограничен только `offer` или только `voting`.

## Если в консоли `orders=0, suitable=0`

В версии v4 симулятор перед поиском заказов делает то же, что водительский интерфейс:
1. выбирает активную машину через `/car/{c_id}/drive`;
2. включает водителя в линию через `/user` с `u_active: 1`;
3. отправляет координаты через `/location`.

Координаты задаются в `config.json`:

```json
"driverLocation": {
  "latitude": 47.221,
  "longitude": 39.633
}
```

Если заказ создан далеко от этих координат, backend может не вернуть его водителю. Поставь координаты рядом с точкой подачи заказа.


## Разные координаты водителей

В `config.json` у каждого водителя можно указать свой блок `location`:

```json
"location": { "latitude": 47.221, "longitude": 39.633 }
```

Если координаты не указаны внутри конкретного водителя, симулятор берёт координаты из массива `driverLocations`. Если и его нет, симулятор автоматически разнесёт водителей вокруг общей точки `driverLocation`, чтобы они не стояли все в одном месте.

## Симуляция движения водителя по заказу

В этой версии эмулятор не просто откликается на заказ, а ведёт себя как водитель:

1. держит каждого водителя на своей координате;
2. после назначения заказа на водителя начинает двигать его к точке подачи;
3. регулярно отправляет новые координаты через `/location`, поэтому машина должна двигаться на карте;
4. когда водитель доехал до клиента, автоматически отправляет `set_arrive_state`;
5. после выбора клиента и прибытия ждёт код/посадку и может сам стартовать поездку;
6. после старта поездки двигает водителя к точке назначения;
7. завершение поездки оставлено ручным по умолчанию, чтобы не ломать тесты и код посадки.

Настройки находятся в `config.json`, блок `tripSimulation`:

```json
{
  "tripSimulation": {
    "enabled": true,
    "moveIntervalMs": 2500,
    "speedToPickupKmh": 28,
    "speedInTripKmh": 38,
    "autoArrive": true,
    "autoStartTrip": true,
    "autoFinishTrip": false
  }
}
```

В текущем архиве `autoStartTrip: true`: после того как клиент сам выбрал водителя, эмулятор доезжает до клиента, ждёт и запускает поездку по коду посадки. Если backend не отдаёт код посадки, эмулятор будет ждать и не будет ломать заказ.

ВАЖНО ПО ПОСЛЕДНЕЙ ВЕРСИИ:
- offer/voting: бот только отправляет кандидатов, клиент выбирает водителя сам.
- обычный заказ: бот может взять заказ напрямую, потому что там нет листания кандидатов.
- после «водитель на месте» обычный/offer стартуют без кода.
- voting стартует подбором кода 1-9, если реальный код не пришёл из backend.
- при запуске симулятор чистит старые активные заказы тестовых аккаунтов. Если это не нужно, поставь cleanupOldActiveOrders=false или cancelExistingActiveOrdersOnStart=false в config.json.
