# Тестовые водители для offer/voting

Что важно в этой версии:

1. `city` и `color` при регистрации больше не отправляются. Бэкенд подтвердил, что эти поля лишние для текущей схемы и могут давать `Db insert failed`.
2. Скрипт регистрации пытается взять реальные `cm_id`, `cc_id`, `seats` из уже рабочих водительских аккаунтов в `config.json`. Поэтому новые тестовые машины создаются по такой же валидной схеме, как у настоящих аккаунтов.
3. По умолчанию создаётся 5 тестовых водителей. После успешной регистрации они сохраняются в `driver-emulator/data/registered-drivers.json`.
4. Эмулятор использует и `registered-drivers.json`, и водителей из `config.json`, поэтому можно работать и с двумя настоящими тестовыми аккаунтами, и с новыми созданными ботами.

## Как запускать

Открой терминал в папке `driver-emulator`:

```bat
cd driver-emulator
npm run register
npm run check
npm run start
```

Если регистрация прошла успешно, в логах будет `Ready drivers: 5/5`, а в `data/registered-drivers.json` появятся новые аккаунты.

## Поведение эмулятора

Для `Предложения / Межгорода` и `Голосования` водитель не выбирается автоматически. Боты только отправляют карточки-кандидаты. Пассажир сам нажимает `Выбрать`. Только после этого выбранный водитель начинает движение.

После выбора пассажиром:

1. выбранный водитель едет к клиенту;
2. у точки клиента ждёт 3 секунды;
3. нажимает `На месте`;
4. ждёт 5 секунд;
5. запускает поездку;
6. едет до конечной точки;
7. ждёт 4 секунды;
8. завершает поездку.

Для voting, если реального кода нет, бот перебирает коды от `1` до `9`. Для обычного заказа и offer старт поездки сначала пробуется без кода.

## Если опять будет `Db insert failed`

Смотри файл:

```bat
data\registration-last-result.json
```

Там будет полный ответ бэкенда. Если ошибка осталась именно по FK, значит у текущих рабочих аккаунтов не удалось прочитать машину, и нужно явно вписать реальные `cm_id` и `cc_id` в `registration.carTemplates` в `config.json`.
