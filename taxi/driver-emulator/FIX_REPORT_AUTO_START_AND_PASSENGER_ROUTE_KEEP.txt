Что исправлено:

1. Эмулятор больше не ждёт ручной ввод кода посадки в тестовом режиме.
   После того как выбранный клиентом водитель доезжает до клиента и переводится в состояние "на месте",
   бот автоматически пробует запустить поездку через set_start_state.

2. Если backend отдал b_driver_code, бот сначала отправляет start с этим кодом.
   Если код не пришёл в ответе API, бот всё равно пробует start без кода, чтобы тестовый сценарий не зависал.

3. В driver-emulator/config.json для тестового сценария выставлено:
   autoStartTrip = true,
   autoStartRequiresCode = false,
   startAfterArriveMs = 1000.

4. На пассажирской карте добавлено сохранение последней построенной линии маршрута.
   Теперь при обновлении заказа, смене состояния водителя или кратком пропадании координат из polling
   линия не сбрасывается сразу в null и не моргает/не исчезает.

5. Сохраняется не только общий маршрут заказа, но и маршрут водитель -> клиент / водитель -> точка назначения.
   Если данные водителя на один polling-цикл пришли пустыми, пассажир всё равно видит последнюю корректную линию.

Проверка:
- driver-emulator/src/simulator.js проверен через node --check.
- src/components/Map/index.tsx проверен через TypeScript transpileModule: синтаксических ошибок нет.
